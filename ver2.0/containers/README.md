# Containers Folder

This folder contains:

- `podman-template.sh`: generic rootless Podman template that generates a native Quadlet `.container` unit
- `container-cloudflare.sh`: Cloudflare Tunnel deployment using Podman secrets and native Quadlet
- `container-code-server.sh`: code-server deployment with Podman secret-backed password
- `container-gitea.sh`: Gitea deployment with persistent data and optional SSH port mapping
- `container-overleaf.sh`: Overleaf app with MongoDB and Redis companion Quadlet units
- `quadlet-doctor.sh`: validator for Quadlet prerequisites and generated services
- `status-all.sh`: one-command status report for all Quadlet services in your user directory

Both scripts write Quadlet files to:

- `~/.config/containers/systemd/`

## Quick usage

```bash
cd ~/homelab.zap-vps/ver2.0/containers
chmod +x *.sh
```

### Deploy Cloudflare tunnel

```bash
./container-cloudflare.sh

# Check Quadlet service
systemctl --user status cloudflare.service
systemctl --user cat cloudflare.service
```

### Deploy code-server

```bash
./container-code-server.sh
systemctl --user status code-server.service
```

### Deploy Gitea

```bash
./container-gitea.sh
systemctl --user status gitea.service
```

If Docker Hub rate-limit is hit, either authenticate or use another registry image:

```bash
podman login docker.io

# or switch registry image
IMAGE=ghcr.io/go-gitea/gitea:latest ./container-gitea.sh
```

Gitea pull behavior can be controlled with `PULL_POLICY` (`always|missing|newer|never`).
Default is `missing` to avoid repeated pull attempts on every restart.

If startup logs show `s6-svscan ... Permission denied`, disable user namespace remapping
for this service:

```bash
USERNS_MODE=none ENABLE_HARDENING=no ./container-gitea.sh
```

### Deploy Overleaf stack (app + mongo + redis)

```bash
./container-overleaf.sh
systemctl --user status overleaf.service overleaf-mongo.service overleaf-redis.service
```

### Deploy another container from template (example: Gitea)

```bash
APP_NAME=gitea \
IMAGE=docker.io/gitea/gitea:latest \
PUBLISH_PORT=3000:3000 \
HOST_DATA_DIR="$HOME/podman_data/gitea/data" \
CONTAINER_DATA_DIR=/data \
./podman-template.sh

# Check Quadlet service generated by template
systemctl --user status gitea.service
systemctl --user cat gitea.service
```

## Resource limits and unlimited mode

All deployment scripts support memory and CPU share tuning.

- `MEMORY_LIMIT`: written to Quadlet `Memory=`
- `CPU_SHARES`: written as Quadlet `PodmanArgs=--cpu-shares=...`

Use any of these values to disable each specific limit:

- `none`
- `off`
- `unlimited`
- `0`

Example:

```bash
MEMORY_LIMIT=none CPU_SHARES=none ./container-cloudflare.sh
```

## Validation and status report

Run a full Quadlet health check:

```bash
./quadlet-doctor.sh
```

Show one-table status for all services:

```bash
./status-all.sh
```

Show only active services:

```bash
SHOW_INACTIVE=no ./status-all.sh
```

## Quadlet generation checks

Use these commands after deployment to confirm Quadlet was generated correctly:

```bash
systemctl --user daemon-reload
systemctl --user cat gitea.service
systemctl --user status gitea.service
systemd-analyze --user --generators=true verify gitea.service
ls -l ~/.config/containers/systemd/gitea.container
journalctl --user -u gitea.service -n 80 --no-pager
```

If service generation fails, inspect generator output:

```bash
/usr/lib/systemd/system-generators/podman-system-generator --user --dryrun
```

## Keep mgrsys services active after logout

Enable lingering once on the host:

```bash
sudo loginctl enable-linger mgrsys
loginctl show-user mgrsys -p Linger
```

Expected value is `Linger=yes`.

## Common warnings

1. SELinux denies bind mounts without labels.
   - Always use `:Z` or `:z`.
2. Rootless Podman can fail on low ports (80/443).
   - Adjust `net.ipv4.ip_unprivileged_port_start` if needed.
3. User services stop after logout.
   - Enable lingering once: `sudo loginctl enable-linger <user>`.
